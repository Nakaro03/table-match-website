- 状態: Bold Posterデザイン実装済み v2.0

- 対象: トップページ、PROJECT / TOPICS / NEWS、運営メンバー、企業向けページ

## 1. 結論

Table MatchのWebサイトを、単なる団体紹介サイトではなく、次の2つを両立する「地域の挑戦機会メディア」に再設計する。

1. 学生が、自分に合うイベント・会社見学・インターンを見つけ、安心して最初の一歩を選べる。
2. 企業が、Table Matchの実績と仕組みを短時間で理解し、出展・協賛・採用支援への投資を判断できる。

トップページの主役は学生とする。企業向け情報を同じ画面で同じ強さにすると訴求がぼやけるため、トップでは企業価値を要約し、判断材料は専用の `/for-companies` に集約する。

サイトの中核メッセージは次とする。

> 同じテーブルから、次の挑戦を。

学生向け補足:

> 話して、見つける。つながって、始める。就職も、起業も、まだ名前のない挑戦も。

企業向け補足:

> 地域企業と学生がホンネで語り合い、インターン・採用・共創へつながる出会いをつくる。

「採用イベント」だけに限定して見せない。学生には可能性と選択肢を広げる場、企業には採用・広報・若者との共創を始める場として位置づける。

## 2. 事業資料からWebへ引き継ぐ価値

紹介資料で一貫している強みは以下である。

- 地域に挑戦する企業と学生が出会い、未来をともにつくる。
- 少人数、双方向、食事形式により、価値観や人柄まで理解できる。
- 経営者と直接話すため、会社のビジョンが学生へ伝わる。
- イベント後も職場体験、インターン、採用まで伴走する。
- 学生運営のネットワークにより、主体性のある学生との接点をつくる。
- 長野・福岡で過去5回開催し、企業9社、学生70名以上、インターン・採用・1dayインターンを含む複数の接続実績が資料上にある。
- 地元テレビLCVの取材実績と、学生・企業双方の具体的な声がある。

Webでは、これを「理念の説明」だけで終わらせず、次の順で見せる。

`理解する → 自分ごと化する → 安心する → 行動する`

## 3. 想定ユーザーと意思決定

| ユーザー | 最初の心理 | 知りたいこと | 最終行動 |
| --- | --- | --- | --- |
| 学生 | 興味はあるが、自分に合うか・勧誘されないか不安 | 誰が来るか、何をするか、費用、服装、一人参加可否、参加後の選択肢 | イベント申込、見学・インターン応募、情報登録 |
| 企業の経営者・採用担当 | 面白そうだが、費用対効果と運営の信頼性が不明 | 対象学生、接触の質、実績、料金、支援範囲、過去企業、リスク | 資料閲覧、相談予約、出展・協賛問い合わせ |
| 大学・自治体・保護者 | 学生に勧めて安全か判断したい | 運営主体、目的、実績、写真、連絡先、個人情報方針 | 紹介、連携問い合わせ |

### 学生に約束する変化

- 参加前: 「やりたいことがまだ分からない」
- 参加中: 「経営者や他の学生と、評価される場ではなく対話できる」
- 参加後: 「自分の興味を言葉にし、見学・インターンなど次の一歩を選べる」

### 企業に約束する変化

- 参加前: 「求人媒体では地域の学生に魅力が伝わらない」
- 参加中: 「少人数で価値観・人柄・自社への関心を相互に確認できる」
- 参加後: 「関心のある学生と職場体験・インターン・採用へ進める。採用以外にも広報や若者との共創に活用できる」

## 4. 心理学的知見を使った設計原則

心理効果は、ユーザーを急かすためではなく、不安と判断負荷を減らし、自分で選べる状態をつくるために使う。

| 原則 | 設計への反映 | 期待する効果 |
| --- | --- | --- |
| 自律性 | CTAを「今すぐ応募」一択にせず、「詳細を見る」「参加を検討する」「企業向け資料を見る」を用意する | 強制感を減らし、自分で決めた感覚を守る |
| 有能感 | 対象者、当日の流れ、所要時間、服装、申込後の流れを具体化する | 「自分でも参加できる」という見通しをつくる |
| 関係性 | 実際の開催写真、学生と経営者の実名・所属つきの声、少人数の説明を見せる | 仲間・運営・参加企業への親近感をつくる |
| 心理的安全性 | 「やりたいことが決まっていなくてもOK」「選考の場ではない」「一人参加可」を目立つ位置で明示する | 発言・質問・参加に伴う対人的リスクを下げる |
| 社会的証明と信頼 | 許諾済み企業ロゴ、開催日つき実績、媒体名、成果の母数・期間・定義を表示する | 未知の団体に対する初期不安を減らす |
| ナラティブ | 「参加前の悩み → 対話 → 次の行動」を1人のストーリーとして見せる | 訪問者が参加後の自分を想像しやすくする |
| 認知負荷の低減 | PROJECT / TOPICS / NEWSの役割を固定し、カードの情報順とCTAを統一する | どこを見て何をすべきか迷わせない |
| 実行意図 | 開催日、場所、対象、費用、締切を一つのチケットUIにまとめ、カレンダー追加を用意する | 「いつ・どこで・何をするか」を具体的行動へ変える |
| シグナリング | 企業名だけでなく、ロゴ、事業の志、社員の顔、学生との具体的な関わりを見せる | 条件表では伝わらない企業の魅力と真剣度を伝える |

根拠となる研究は末尾「参考資料」に記載する。

## 5. 情報設計

### 5.1 グローバルナビゲーション

デスクトップ:

`ロゴ | PROJECT | TOPICS | NEWS | Table Matchとは | 企業の方へ | 次回イベント`

- 主CTA: `次回イベントを見る`（オレンジ）
- 企業CTA: `企業の方へ`（テキスト＋外向き矢印）
- ヘッダーは白背景を基本とし、スクロール後も固定する。
- モバイルでは下部に `イベントを見る` を固定表示し、企業導線はメニュー内に置く。

### 5.2 サイトマップ

```text
/
├── /projects
│   └── /projects/[slug]
├── /topics
│   └── /topics/[slug]
├── /news
│   └── /news/[slug]
├── /about
├── /team
├── /for-companies
├── /companies/[slug]
├── /apply/[project-slug]
└── /contact
```

初期公開時にCMSを導入しない場合も、このURL構造を先に固定する。

### 5.3 PROJECT / TOPICS / NEWSの役割

QWSの3分類を参考にするが、Table Matchでは次の意味に限定する。

| 分類 | ユーザーへの約束 | 掲載するもの | 掲載しないもの |
| --- | --- | --- | --- |
| PROJECT | 今、参加・応募できる機会 | イベント、会社見学、インターン募集、共創プロジェクト | 開催報告、プレス掲載だけの記事 |
| TOPICS | 人・会社・体験を深く知る | 会社見学レポート、インターン体験談、学生・経営者インタビュー、TV取材記事 | 日付だけの公式連絡 |
| NEWS | 公式の更新を時系列で確認する | 開催決定、申込開始、登壇企業決定、メディア掲載、募集終了 | 詳細な体験談や長文レポート |

同じ出来事を重複投稿しない。たとえばNEWSの「第6回開催決定」は、詳細を持つPROJECTページへリンクする。

### 6.1 HERO仕様

ポスター案Bの強さを採用しつつ、実運用では情報を絞る。

- Eyebrow: `学生 × 経営者 / 長野・福岡`
- H1: `同じテーブルから、次の挑戦を。`
- 本文: `話して、見つける。つながって、始める。就職も、起業も、まだ名前のない挑戦も。`
- 主CTA: `次回イベントを見る`
- 副CTA: `Table Matchとは`
- 右上または下部にNEXT EVENTチケットを表示する。
- 写真は生成画像ではなく、実際のTable Match開催写真を使用する。人物の顔、食卓、対話の様子が見える写真を優先する。
- 「参加者募集中」は申込URLが有効な場合のみ表示する。未確定時は `開催情報を受け取る` に変更する。

### 6.2 PROOF BAR仕様

数字は大きく見せるが、定義を必ず付ける。

例:

- `5回` 過去開催数（2026年7月時点）
- `70名+` 累計参加学生（事業資料記載値、公開前確認）
- `9社` 累計参加企業（同上）
- `LCV` TV取材実績

`100%満足度`、`ROI 836%以上` は、母数・調査日・計算式を示せない間はトップへ掲載しない。

### 6.3 PROJECTカード仕様

カードの順序を統一する。

1. 種別: `EVENT / INTERNSHIP / COMPANY VISIT`
2. 募集状態: `募集中 / 予告 / 締切`
3. タイトル
4. 開催企業ロゴまたは実写
5. 日付、場所、対象、費用
6. 得られる体験を1文
7. CTA

「募集終了」を消さず、開催実績として残す。ただし一覧初期表示は募集中を優先する。

### 6.4 参加者の声仕様

匿名の「参加学生A」「IT系企業」だけでは証拠として弱い。本人・企業の許諾を取ったうえで、次を表示する。

- 顔写真またはイベント写真
- 氏名またはイニシャル
- 大学・学年 / 会社名・役職
- 参加回
- 参加前の悩み
- 当日の発見
- その後の行動

短い引用カードから、詳細TOPICへ遷移させる。

### 6.5 運営メンバーページ仕様

学生自身が企画・営業・広報・当日運営を担っていることを、団体の信頼性と参加価値として伝える。

- URL: `/team`
- H1: `この出会いを、学生の手でつくる。`
- 代表紹介: 中村楼偉の写真、所属、設立の想い、詳細プロフィール
- 長野支部: 8名を4列グリッドで掲載
- 福岡支部: 6名を3列グリッドで掲載
- 各カード: 写真、氏名、担当、大学・学年
- 写真未登録時は、生成した人物写真を使わずイニシャル表示にする
- 最終CTA: `運営メンバーについて問い合わせる`
- メンバーの上下関係より、地域を越えて対等に運営するチームとして見せる

## 7. 企業向けページ設計

企業の出資・出展判断では、情緒だけでなく「対象・仕組み・成果・費用・リスク」が必要である。ページは次の順にする。

1. ファーストビュー
   - H1: `求人票では伝わらない会社の魅力を、3時間の対話で。`
   - 主CTA: `企業向け資料を見る`
   - 副CTA: `30分相談する`
2. 企業が抱える課題
   - 地域学生との接点不足
   - 条件比較だけでは志や文化が伝わらない
   - 面接前に価値観や人柄を知れない
3. Table Matchの仕組み
   - 対面イベント → 相互理解 → 職場体験・インターン → 採用・共創
4. 参加価値
   - 採用: 関心学生と深く話せる
   - 広報: 会社の志・技術・経営者の人柄を記事化できる
   - 共創: 学生の視点を事業・地域課題へ活かせる
5. 実績
   - 開催回、学生、企業、インターン・採用接続、TV取材
   - すべて期間・定義・母数を付ける
6. ケーススタディ
   - 課題 → 当日の設計 → 学生反応 → 次の行動 → 企業コメント
7. 他手段との比較
   - 合同説明会、求人媒体、Table Match
   - 接触時間、双方向性、学生理解、イベント後支援で比較
   - 競合サービスを断定的に否定せず、Table Matchが適する条件を示す
8. プラン・費用
   - 含まれるもの、追加費用、キャンセル、実施地域、支援範囲
9. よくある質問
10. 資料閲覧 / 相談CTA

### 7.1 企業向け資料

既存の事業スライドはWebから閲覧・ダウンロードできるようにする。フォームで個人情報を取る場合は、入力前に資料の目次と得られる情報を示す。

推奨資料構成:

- Table Matchの目的
- 学生と地域企業の課題
- イベント形式と採用までの流れ
- 開催・接続実績
- 参加企業と学生の声
- 他手段との違い
- 企業プラン、費用、支援内容
- 実施までのスケジュール
- 運営体制、規約、問い合わせ先

## 8. 参加企業ロゴの扱い

現在の会社名マルキーは廃止し、Wantedlyの事例を参考に静的な企業ロゴグリッドへ変更する。

- 企業ごとに掲載許諾を取る。
- ロゴは公式データを受領し、縦横比を変えない。
- 通常はモノクロまたは低彩度、hover/focusでブランドカラーにする。
- 企業名の代替テキストを付ける。
- クリック先はTable Match内の企業紹介または関連PROJECTへ統一する。
- 自動横流しを必須にしない。動かす場合も停止操作と `prefers-reduced-motion` 対応を行う。
- ロゴ数が少ない段階では、無限ループにせず整列グリッドで見せる。

ロゴは「参加・協賛・取材・提携」を混同しない。見出しを `参加企業` など関係性が分かる言葉にする。

## 9. Table Matchロゴ改変仕様

添付された、青い学生とオレンジの経営者がテーブルを挟んで向き合う案を正式な方向性とする。

### 必須成果物

- 横組みロゴ: シンボル + `Table Match`
- シンボル単体: favicon、SNSアイコン、モバイルヘッダー用
- 単色版: 黒、白
- SVG、PNG 1x/2x
- セーフエリアと最小表示サイズの規定

### 修正方針

- 青=学生、オレンジ=企業という役割色を維持する。
- テーブル越しの対話が16〜24pxでも判別できるよう線を簡略化する。
- アイコン下の小さな `Table Match` と右側の大きなワードマークが重複する構成は、横組み版では避ける。
- `Table` はコバルト、`Match` はオレンジを基本とする。
- 人物を上下関係ではなく同じ目線・同じ大きさで描く。
- 現在の `public/logo.jpg` は `CONNCES` など表記に問題があり、正式ロゴには使用しない。
- `public/icon.svg` の食器モチーフは、新シンボルへ差し替える。

## 10. ビジュアルデザインシステム

### 10.1 方向性

`Bold Youth Event Poster` を採用する。大学祭の活気と、地域企業が出資判断できる信頼感を両立する。

- Swiss poster型の強いグリッド
- 大きな日本語見出し
- 色面、太い罫線、矢印、チケット表現
- 実写を幾何学的に切り抜く
- 影やグラデーションに頼らず、色・サイズ・余白で階層化する

トップは強く、本文は落ち着かせる。全セクションをポスター化すると読み疲れが起きるため、オレンジ・青の全面背景は主要CTAと章の切替だけに使う。

### 10.2 カラー

| 用途 | 推奨色 | 役割 |
| --- | --- | --- |
| Primary Blue | `#0757C8` | 学生、信頼、見出し、リンク |
| Action Orange | `#FF4B0A` | 主CTA、企業、NEXT表示 |
| Accent Yellow | `#FFD400` | 矢印、番号、注目補助 |
| Paper | `#F7F4EC` | 背景 |
| Ink | `#111111` | 本文・罫線 |
| White | `#FFFFFF` | 色面上の文字 |

色だけで種別や状態を伝えず、必ずテキストラベルを併用する。

### 10.3 タイポグラフィ

- 日本語: Noto Sans JP
- 欧文・数字: Space Groteskまたは可読性の高いコンデンス系
- H1: 64〜96px（desktop）、40〜52px（mobile）
- H2: 40〜64px（desktop）、30〜40px（mobile）
- 本文: 16〜18px、行間1.7前後
- ラベル: 12〜14px、英字は字間を広げる
- 本文を太字だらけにせず、太字は見出しと行動語へ限定する。

### 10.4 写真

- 生成された人物画像はレイアウト検証用に限定し、本番は実際の開催写真へ置き換える。
- 写真の説明と撮影クレジットを付ける。
- 顔が小さすぎる集合写真だけでなく、1対1や少人数の対話が伝わる写真を使う。
- 学生だけ、経営者だけに偏らず、同じテーブルにいる構図を優先する。

## 11. UI・レスポンシブ・アクセシビリティ

- 主要CTAは最小44×44px。
- 通常本文と背景はWCAG AA相当のコントラストを確保する。
- 矢印やカード全体だけにクリックを任せず、リンク名を明示する。
- キーボード操作、focus表示、skip linkを実装する。
- 動くロゴ列、写真スライド、装飾アニメーションは停止可能にする。
- `prefers-reduced-motion` では自動切替と大きな移動を止める。
- イベント日時は見た目だけでなくHTMLの `time` 要素で持つ。
- 募集終了、満席、開催延期を色以外のラベルでも示す。
- モバイルではHEROを1画面に詰め込まず、メッセージ → 写真 → NEXTチケットの縦順にする。
- 申込フォームは入力項目を最小化し、所要時間と個人情報の利用目的を先に表示する。

## 16. 受け入れ基準

- 初見の学生が5秒以内に「学生と経営者が対話する場」と理解できる。
- ファーストビュー内に学生向け主CTAが1つだけ強く表示される。
- 企業は2クリック以内に資料または相談導線へ到達できる。
- PROJECT / TOPICS / NEWSのどれに掲載すべきか運営者が迷わない。
- 募集中の企画には日付、場所、対象、費用、状態、CTAがある。
- 実績数値には期間・定義・母数のいずれか必要な注記がある。
- 参加企業ロゴは許諾済みで、縦横比・代替テキスト・関係性表記が正しい。
- 主要ページはmobile 360pxからdesktop 1440pxまで破綻しない。
- キーボード操作、reduced motion、コントラストを確認済みである。
