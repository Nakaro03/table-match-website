# Table Match サイト チーム開発マニュアル

このサイトは **`main` ブランチに反映されると自動で本番公開**されます。
事故を防ぐため、**直接 main を編集せず「ブランチ＋プルリク（PR）」で進めます**。

おおまかな流れ：

```
最新を取得 → 自分のブランチを作る → 編集 → 保存(commit) → 送信(push)
→ プルリク(PR)を作る → オーナーが確認・承認 → main に反映 → 自動で本番公開
```

---

## 0. はじめに（各メンバーが最初の1回だけ）

1. GitHub アカウントを作る（https://github.com）
2. オーナーから届く **招待メール / 通知** の「Accept invitation」を押す
3. ツールを用意する。**プログラミングに不慣れなら「GitHub Desktop」がおすすめ**（マウス操作中心）
   - GitHub Desktop: https://desktop.github.com からダウンロード＆ログイン
   - コマンドに慣れている人は git だけでもOK

> サイトを自分のPCで動かして確認したい場合は、別途 Node.js 20以上 と pnpm が必要です（巻末の「おまけ」参照）。文章や画像の修正だけなら無くても進められます。

---

## A. GitHub Desktop でのやり方（おすすめ・初心者向け）

### ① リポジトリを自分のPCに取り込む（最初の1回）
1. GitHub Desktop を開く → **File → Clone repository**
2. `Nakaro03/table-match-website` を選んで **Clone**

### ② 作業を始める前に「最新」にする（毎回）
- 上部の **Fetch origin** を押す → `main` が選ばれている状態で **Pull** で最新を取り込む

### ③ 自分のブランチを作る（作業ごと）
1. 上部の **Current branch** をクリック → **New branch**
2. わかりやすい名前をつける（例 `fix-event-date`、`update-hero-text`）
3. **Create branch**

> ブランチ名は「何をするか」がわかる英数字で。日本語より英数字＋ハイフンが安全。

### ④ ファイルを編集する
- エディタ（VSコードなど）でファイルを直して **保存**

### ⑤ 保存を記録する（commit）
1. GitHub Desktop の左下に変更したファイルが出る
2. 下の **Summary** 欄に「何をしたか」を一言（例 `イベント日程を更新`）
3. **Commit to （ブランチ名）** を押す

### ⑥ GitHub に送る（push）
- 上部の **Push origin** を押す

### ⑦ プルリク（PR）を作る
1. push 後に出る **Create Pull Request** を押す（ブラウザが開く）
2. タイトルと、何を変えたかを書く
3. **Create pull request** を押す
4. オーナーに「PR出しました」と連絡

### ⑧ 承認・反映を待つ
- オーナーが内容を確認して **Merge**（承認）すると `main` に反映 → **自動で本番公開**
- 修正を求められたら、同じブランチで ④〜⑥ を繰り返せばPRに自動で反映されます

## B. コマンド（git）でのやり方

```bash
# ① 最初の1回だけ：取り込む
git clone https://github.com/Nakaro03/table-match-website.git
cd table-match-website

# ② 作業前：最新の main にする（毎回）
git checkout main
git pull

# ③ 自分のブランチを作る
git checkout -b fix-event-date     # 名前は作業内容に合わせる

# ④ ファイルを編集（エディタで）

# ⑤ 保存を記録（commit）
git add -A
git commit -m "イベント日程を更新"

# ⑥ GitHub に送る（push）
git push -u origin fix-event-date

# ⑦ 表示されるURLを開いてプルリク作成、またはGitHubの画面で "Compare & pull request"
```

承認後、次の作業はまた②から始めます。

---

## C. オーナーがやる初期設定（main を保護する・最初の1回）

これをやると「PRを通さないと main に入れられない」ようになり、事故を防げます。

1. https://github.com/Nakaro03/table-match-website → **Settings**
2. 左メニュー **Branches** → **Add branch ruleset**（または Add rule）
3. **Branch name pattern** に `main` を入力
4. 次にチェックを入れる：
   - ✅ **Require a pull request before merging**（PR必須にする）
   - （任意）**Require approvals**：1 にすると承認1件が必要
5. **Create / Save** で保存

> これで、誰かが間違えて main に直接 push しようとしても止まり、必ずPR経由になります。

---

## D. 困ったときのルール

- **コンフリクト（competing changes）と出た**：同じ箇所を別の人が編集した状態。あわてず、オーナーに相談
- **本番サイトが変**：直前にマージしたPRが原因のことが多い。オーナーがそのPRを Revert（取り消し）すれば元に戻せる
- **迷ったら main を直接いじらない**。必ず自分のブランチで作業する

## おまけ：自分のPCでサイトを動かして確認する（任意）

文章・画像修正だけなら不要ですが、見た目を手元で確認したい場合：

```bash
# Node.js 20以上 と pnpm が必要
pnpm install      # 最初の1回（必要なパッケージを入れる）
pnpm dev          # 開発サーバー起動
```

→ ブラウザで http://localhost:3000 を開くと確認できます（`Ctrl+C` で停止）。
